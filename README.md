# 소상공인 정책자금 안내 및 추천 서비스

공식 사이트의 정책자금 공고와 첨부 원본을 검증된 수집 코드로 S3 RAW에 보존하고, 별도 Agent가 정형화한 데이터를 Snowflake와 시멘틱 레이어로 조회해 기업 상황에 맞는 자금을 대화로 안내하는 프로젝트입니다. AI + Playwright MCP는 초기 사이트 탐색·코드 작성과 장애 분석·수정에 활용하고, 정상 수집은 Python Playwright 코드로 반복 실행합니다.

현재 구현 순서는 `2026-09-21` 기준 [RAW 수집·가공 분리 설계](docs/16_RAW_수집_가공_분리_설계.md)를 따릅니다. SEMAS 공지사항의 목록·상세·첨부를 수집하는 Python Playwright 코드와 로컬/S3 저장 코드가 구현되어 있으며, 제한된 로컬 실사이트 검증을 완료했습니다. 실제 S3 저장 실증·Docker·EC2·Airflow 연결은 아직 진행하지 않았습니다. 이후 [대화형 정책자금 안내 전환계획](docs/15_대화형_정책자금_안내_전환계획.md)에 따라 AI가 기본 기업 상태를 질문한 뒤 근거와 함께 답변하도록 구현합니다.

## 문서로 개발 작업 시작하기

- [AGENTS.md](AGENTS.md): Codex가 읽을 프로젝트 지침 진입점
- [GPT.md](GPT.md): 공통 개발·보안·환경·검증 규칙
- [첫 수집기 구현 지시서](docs/tasks/01_collector_mvp.md): 필요한 입력, 만들 코드, 제외 범위와 합격 기준
- [수집기 실행·장애 대응 안내](docs/runbooks/collector.md): 구현 상태, 실행 준비, 결과 확인, 진단·수정·복구 절차
- [전체 문서 위치와 읽는 순서](docs/00_기획문서_읽기순서.md): 설계·작업·운영·후속 참고 문서 지도

AI에게 구현 지시서를 읽고 작업하도록 요청한 뒤 검증된 코드를 운영합니다. 문서를 수정한다고 코드 생성·실제 수집·운영 배포가 자동 시작되지는 않습니다. 현재 수집 명령은 로컬과 S3 모드를 명시적으로 선택해 실행합니다.

## 문제 인식

소상공인은 정책자금이 필요해도 다음과 같은 이유로 신청을 어렵게 느낍니다.

- 정책자금을 운영하는 기관이 여러 곳에 나뉘어 있음
- 자금별 신청 조건과 필요 서류가 복잡함
- 심사 과정이 길고 어렵게 느껴짐
- 본인 사업장이 어떤 자금에 해당되는지 판단하기 어려움

이 서비스는 정책자금 정보를 단순히 나열하는 것이 아니라, 사용자의 사업 상태를 기준으로 적합한 자금을 안내하는 것을 목표로 합니다.

## 핵심 목표

- 소상공인이 정책자금 제도를 쉽게 이해할 수 있게 한다.
- 공고 본문과 PDF/HWP 원본을 S3에 버전별 보존하고, 재수집 없이 다시 가공할 수 있게 한다.
- 공식 자료를 검증해 Snowflake에 정형 저장하고 시멘틱 레이어로 조회 기준을 통일한다.
- 대화에서 필요한 기업 상태를 확인하고 신청 가능성이 있는 자금 후보를 안내한다.
- 자금 신청에 필요한 서류와 발급 방법을 한곳에서 안내한다.
- 자금 안내에 원문 근거, 추가 확인 조건, 공식 링크와 데이터 기준일을 제공한다.

## 주요 기능

### 1. 정책자금 기관 소개

정책자금을 제공하거나 연계하는 주요 기관을 소개합니다.

대화에서 안내할 콘텐츠:

- 기관별 역할 소개
- 제공하는 자금 유형 안내
- 공식 사이트 및 신청 페이지 연결
- 기관별 상담 또는 문의 경로 안내

예시 기관:

- 소상공인시장진흥공단
- 중소벤처기업부
- 지역 신용보증재단
- 신용보증기금
- 기술보증기금

### 2. 해당되는 자금 확인하기

사용자가 프롬프트로 자금을 물으면 AI가 부족한 기업 상태를 질문하고, 확인된 조건으로 게시된 정책자금 데이터를 조회해 안내합니다. 이미 답한 항목은 다시 묻지 않고, 후보에 따라 필요한 후속 질문을 추가합니다.

기본 정보와 후보별 후속 질문 항목:

- 사업자 유형
- 업력
- 매출 규모
- 상시 근로자 수
- 업종
- 지역
- 신용 상태
- 창업 여부
- 피해 또는 위기 상황 여부
- 보증 가능 여부

추천 결과에는 다음 정보를 포함합니다.

- 추천 자금명
- 신청 가능성이 있는 이유
- 주요 신청 조건
- 신청 기관
- 필요 서류
- 신청 전 확인해야 할 주의사항

### 3. 자금에 필요한 서류 출력 방법

정책자금 신청에 자주 필요한 서류와 발급 방법을 안내합니다.

예상 서류:

- 사업자등록증명
- 부가가치세 과세표준증명
- 소득금액증명
- 납세증명서
- 지방세 납세증명서
- 4대보험 관련 서류
- 재무제표 또는 매출 증빙 자료
- 임대차계약서

각 서류별로 다음 정보를 제공합니다.

- 서류의 용도
- 발급 가능한 사이트
- 발급 절차
- 온라인 발급 가능 여부
- 발급 시 주의사항

### 4. 챗봇 문의 기능

대화형 자금 안내는 초기 구현 범위입니다. 시멘틱 레이어가 데이터의 의미와 조회 기준을 제공하고, 대화 Agent가 기업 상태 확인·후속 질문·도구 조회·답변을 담당합니다.

지원 조건은 승인된 정형 데이터와 조회 SQL 또는 검증 함수로 비교합니다. 모르는 정보는 미확인 상태로 유지하며, 프롬프트나 모델의 사전지식만으로 자격 충족을 결정하지 않습니다.

## MVP 범위

초기 버전은 다음 순서로 구현합니다.

1. AI + Playwright MCP로 URL 하나의 수집 코드·테스트를 작성하고, 검증된 코드로 HTML/본문/PDF/HWP 원본과 운영 메타데이터·ID·해시·개정본을 S3 RAW에 저장
2. 동일 공고·본문 수정·첨부 교체·부분 실패·조용한 누락 검증 후 여러 기관으로 확장하고, Docker/EC2 재현 검증 뒤 Airflow 주간 실행 연결
3. 정책자금 스키마 설계 후 두 번째 Agent로 S3 RAW를 구조화 추출·검증하고 Snowflake에 정형 적재, 검토·게시 버전 관리
4. 게시 데이터 위의 시멘틱 레이어 정의와 조회 검증
5. 프롬프트 요청에 기업 상태를 질문하고 근거 기반으로 답하는 대화형 안내

수집 코드는 정책자금 조건을 해석하지 않습니다. RAW 저장 완료가 수집의 종료 지점이며, 두 번째 Agent의 재처리는 저장된 원본 버전을 사용합니다. 정상 수집은 LLM·MCP·Codex 앱 없이 실행 가능하게 합니다. 매칭 배치 DAG는 기업 프로필 저장·정기 재평가가 필요할 때 추가합니다.

MVP에서 제외하는 기능:

- 별도 추천 REST API와 기업정보 입력 폼
- 전용 웹 UI와 관리자 CMS
- 사용자 회원가입 및 로그인
- 실제 대출 신청 연동
- 신청 진행 상태 추적
- 기관별 실시간 심사 결과 조회

## 기본 사용자 흐름

1. 사용자가 대화 화면에서 “우리 회사에 맞는 정책자금을 알려줘”라고 질문한다.
2. AI가 업종·지역·업력 등 부족한 기본 기업 상태를 질문한다.
3. 답변으로 후보를 좁히고 자금별로 필요한 추가 조건을 확인한다.
4. 시멘틱 레이어에 정의된 의미와 조건을 사용해 게시 데이터를 조회·비교한다.
5. 자금 후보, 추천 근거, 미확인 조건, 필요 서류, 공식 링크와 데이터 기준일을 안내한다.
6. 사용자가 상태를 수정하거나 추가 질문하면 다시 조회해 답변한다.

## 데이터 관리 방향

정책자금 정보는 변경될 수 있으므로 공식 기관 자료를 기준으로 관리합니다.

AI가 사이트 구조를 확인해 공통 수집기와 기관별 설정·어댑터를 작성하고, 정기 실행은 그 코드가 목록·본문·첨부를 탐색해 S3에 저장합니다. 공고의 고정 ID와 내용 해시를 구분하고, 본문 또는 첨부 변경 시 이전 원본을 유지한 채 새 버전을 저장합니다. 부분 실패와 조용한 누락은 정상 완료본과 구분합니다. 장애 수정은 증거 기반 분석·테스트·승인 뒤 적용하며 운영 코드를 자동 교체하지 않습니다.

별도 가공 Agent는 완료된 RAW 버전을 읽고 추출·검증 코드를 거쳐 Snowflake에 저장합니다. 검증 PASS와 게시 승인을 구분하며 대화 Agent는 게시 데이터만 조회합니다. 시멘틱 레이어는 데이터의 의미와 관계를 정의하는 별도 관리 대상입니다. PostgreSQL은 향후 웹서비스 운영 기능이 필요할 때 도입을 재검토합니다.

관리해야 할 주요 데이터:

- 기관 정보
- 정책자금 정보
- 신청 조건
- 필요 서류
- 서류 발급 경로
- 신청 링크
- 업데이트 날짜

정책자금 추천 결과에는 항상 최신성 확인을 위한 기준일을 표시하는 것이 좋습니다.

government-backed-funding/

├── frontend/                  # 후속 웹 UI 공간

작업·운영 문서는 작성되어 있지만 애플리케이션 디렉터리는 구현 예정 위치이며 아직 서비스 구현을 뜻하지 않습니다. 기관별 어댑터와 테스트는 `workers/collector/adapters/`, `tests/collector/`에 구현할 예정입니다. RAW 메타데이터 계약은 수집 구현 시 `schemas/raw/metadata_v1.json`에 추가할 예정이며, 기존 `schemas/policy_fund/v1.json`을 RAW 필수 스키마로 사용하지 않습니다. `docker-compose.yml`은 서비스가 등록되지 않은 구성 골격입니다. 문서 읽기는 [00_기획문서_읽기순서.md](docs/00_기획문서_읽기순서.md)를 참고합니다.

## 프로젝트 전용 Python 환경

Python은 `3.13.15`, uv는 `0.12.15`를 사용합니다. 설치된 전역 Python·Homebrew uv와 셸 PATH를 변경하지 않고, 이 저장소의 `./uv` 실행 파일로 프로젝트 도구를 사용합니다.

| 경로 | 역할 | Git 포함 |
| --- | --- | --- |
| `.tools/uv/` | 프로젝트 전용 uv 실행 파일 | 아니오 |
| `.tools/python/` | 프로젝트 전용 Python 설치 | 아니오 |
| `.tools/cache/`, `.tools/python-cache/`, `.tools/bin/` | 다운로드 캐시와 실행 링크 | 아니오 |
| `.venv/` | 프로젝트 패키지 가상환경 | 아니오 |
| `.python-version` | 사용할 Python 패치 버전 | 예 |
| `pyproject.toml` | Python 허용 범위·uv 버전·의존성 정의 | 예 |
| `uv.lock` | 해석된 패키지 버전 | 예 |
| `uv` | 프로젝트 경로와 도구 저장 위치를 설정하는 실행 파일 | 예 |

프로젝트 루트에서 실행합니다. 별도로 가상환경을 활성화하지 않아도 됩니다.

```bash
./uv --version
./uv sync --locked
./uv run python --version
```

일반 `uv` 명령은 기존 전역 설치를 가리킬 수 있으므로 이 프로젝트에서는 `./uv`를 사용합니다. 초기 의존성 목록은 비어 있으며, 수집 도구를 선정한 뒤 `./uv add 패키지명`으로 추가하고 `pyproject.toml`과 `uv.lock`을 함께 관리합니다. `.venv` 내부 파일을 직접 수정하지 않습니다.

새로 복제한 저장소에는 `.tools/`가 없으므로 공식 설치 프로그램을 내려받아 프로젝트 경로를 지정해 설치합니다. 아래 명령은 macOS/Linux 셸 기준이며, 셸 설정이나 전역 설치 경로를 변경하지 않습니다. [uv의 프로젝트 경로 설치 옵션](https://docs.astral.sh/uv/reference/installer/#unmanaged-installations)

```bash
setup_tmp=$(mktemp -d)
curl --fail --location --proto '=https' --tlsv1.2 \
  https://releases.astral.sh/github/uv/releases/download/0.12.15/uv-installer.sh \
  --output "$setup_tmp/uv-installer.sh"
env UV_UNMANAGED_INSTALL="$PWD/.tools/uv" sh "$setup_tmp/uv-installer.sh"
./uv python install 3.13.15
./uv sync --locked
```

프로젝트 폴더를 다른 경로로 옮기면 기존 `.venv`가 이전 Python 경로를 참조할 수 있습니다. 이 경우 해당 환경을 별도 이름으로 보관하고, 옮긴 폴더에서 위 설치·동기화 절차로 가상환경을 다시 만듭니다.
