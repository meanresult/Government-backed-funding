# 02. 기능요구사항

## 현재 적용 요구사항 — 2026-09-18

현재 구현 목표는 `검증된 수집 코드 → S3 RAW → 별도 가공 Agent → 검증·Snowflake → 시멘틱 레이어 → 대화형 자금 안내`다. AI + Playwright MCP는 초기 코드 구축과 장애 분석·수정에 사용하며 정상 수집의 필수 실행환경으로 두지 않는다. 수집·가공 경계는 [16_RAW_수집_가공_분리_설계.md](16_RAW_수집_가공_분리_설계.md), 첫 구현은 [작업 지시서](tasks/01_collector_mvp.md), 후속 대화는 [15_대화형_정책자금_안내_전환계획.md](15_대화형_정책자금_안내_전환계획.md)를 따른다.

### 먼저 구현할 RAW 수집 요구사항

| ID | 요구사항 |
| --- | --- |
| `RI-01` | AI가 Playwright MCP로 승인된 사이트를 확인해 공통 수집기와 기관별 설정·어댑터를 작성한다. 검증된 코드가 정상 수집을 반복 실행한다. |
| `RI-02` | 수집 코드는 상세 HTML/DOM·본문과 PDF/HWP 원본을 확보하며 정책자금 조건을 해석하지 않는다. |
| `RI-03` | S3에 원본, 고정 공고 ID, 수집 시각, URL, 해시, 파일 위치, 수집 상태를 보존한다. 비즈니스 스키마는 요구하지 않는다. |
| `RI-04` | 본문·첨부 해시로 신규/수정을 감지하고 불변 버전을 저장한다. 변경 없음도 재확인 이력에 남긴다. |
| `RI-05` | 첨부 실패·탐색 범위 미완료·업로드 실패를 성공과 구분한다. 완료 manifest만 가공 대상에 노출한다. |
| `RI-06` | URL 하나의 실제 수집·S3 재조회·동일/변경/첨부 교체·실패 재시도를 검증한 뒤 다기관으로 확장한다. |
| `RI-07` | 검증된 수집 작업에만 Airflow 주간 배치를 연결한다. 과거 공고 재확인 범위와 누락을 기록한다. |
| `RI-08` | 목록·페이지 순회·본문·첨부 완전성을 검증하고, 실제 신규 0건과 조용한 수집 실패를 구분한다. 코드 버전·설정 해시·실패 증거를 남긴다. |
| `RI-09` | 실패 원인을 분류하고 AI 수정안을 테스트한 뒤 승인된 버전만 운영에 적용한다. 운영 코드 자동 교체·배포는 하지 않는다. |
| `RI-10` | 정상 수집은 LLM·MCP·Codex 앱 없이 headless 실행 가능해야 한다. 로컬 실증 후 버전 고정 Docker 환경과 EC2에서 재검증한다. |

### 후속 저장·대화 요구사항

| ID | 요구사항 |
| --- | --- |
| `CF-01` | 수집은 `RI-01~10`에 따라 S3 RAW 완료로 종료한다. 두 번째 Agent는 별도 작업에서 완료된 RAW 버전을 읽는다. |
| `CF-02` | 가공 단계에서 정책자금 스키마를 설계하고 추출 결과를 코드로 검증해 근거·이력과 함께 Snowflake에 정형 저장한다. 원본/처리 버전으로 재처리를 추적한다. |
| `CF-03` | 검증과 게시 승인을 구분하며, 승인된 데이터 위에 시멘틱 레이어를 정의한다. |
| `CF-04` | 사용자가 프롬프트로 자금을 물으면 대화에서 부족한 기업 상태를 질문한다. |
| `CF-05` | 확인된 기업 상태로 자금을 조회하고 조건 충족·미확인 항목을 구분해 답변한다. |
| `CF-06` | 답변에 추천 근거·추가 확인사항·서류·공식 링크·데이터 기준일을 제공한다. |
| `CF-07` | 정보 부족, 데이터 없음, 도구 장애를 구분하고 질문·조회·답변을 검증한다. |

먼저 `RI-01~06`의 단일 URL 실증과 `RI-08~09`, `RI-10`의 headless 코드 실행을 검증한다. 이후 다기관·Docker/EC2 검증과 `RI-07`, 이어서 가공·게시·시멘틱 레이어(`CF-01~03`)와 대화(`CF-04~07`)를 구현한다. 별도 추천 REST API, 입력 폼, 전용 웹 UI와 관리자 CMS는 후속 범위다. 기업별 매칭 배치 DAG도 초기 필수 범위가 아니다. 기존 `FR-*` 식별자는 과거 문서 참조를 위해 보존하며, 아래의 `챗봇 MVP 제외`와 `선택/검색 전용 입력`은 현재 범위에 적용하지 않는다. 기존의 게시 승인·원문 근거·민감정보 최소 보관 원칙은 유지한다.

## 이전 웹서비스 요구사항 — 후속 구현 참고

정책자금 추천 웹사이트의 기능 요구사항 문서입니다. 본 문서는 현재 스토리보드, 운영 방향, MVP 의사결정을 기준으로 사용자 기능과 운영 기능을 정리합니다.

## 문서 범위

- 기준일: `2026-05-01`
- 대상 서비스: 정책자금 추천 웹사이트
- 기준 산출물: 스토리보드 `S1` ~ `S5`

## 제품 목표

사용자가 자신의 사업 조건을 선택 또는 검색 기반으로 입력하면, 시스템이 신청 가능성이 있는 정책자금과 필요 서류를 함께 추천하고, 상세 자금 정보와 서류 발급 방법까지 이어서 제공하는 것을 목표로 합니다.

동시에 운영자는 공고 문서를 업로드하면 시스템이 변경 여부를 검토하고, 초안 규칙을 생성한 뒤 관리자 승인 후에만 운영 규칙에 반영되도록 관리할 수 있어야 합니다.

## 사용자 역할

### 1. 일반 사용자

- 정책자금 추천을 받는 일반 사용자
- 사업 상태를 입력하고 추천 자금, 필요 서류, 발급 방법을 확인하는 사용자

### 2. 관리자

- 로그인한 관리자만 접근 가능한 운영 사용자
- 필요 서류 콘텐츠와 정책자금 규칙을 관리하고 승인하는 사용자

## MVP 범위

MVP 범위에는 아래 요구사항을 포함합니다.

- `FR-01` 기업 정보 입력
- `FR-02` 정책자금 추천 결과 반환
- `FR-03` 사용자 맞춤 필요 서류 반환 
- `FR-04` 자금 상세 정보 조회
- `FR-05` 서류 발급 방법 조회
- `FR-06` 필요 서류 콘텐츠 관리
- `FR-07` 정책자금 규칙 업데이트 및 승인 관리

아래 요구사항은 MVP 이후 확장 범위로 분리합니다.

- `FR-08` 챗봇 기반 질의응답

## 입력 정책

- 사용자 입력 방식은 `선택`과 `검색` 중심으로 통일합니다.
- 금액 관련 항목은 자유 텍스트 입력보다 `선택형 구간값` 중심으로 제공합니다.
- 추천에 필요한 기업 정보는 단계형 입력 경험으로 구성합니다.
- 입력값은 추천 규칙 엔진이 평가할 수 있는 구조화 데이터 형태로 전달되어야 합니다.

## 민감 입력값 처리 정책

- `신용점수`, `기대출`은 추천 요청 시점의 평가 입력값으로 사용합니다.
- MVP에서는 raw 값을 영구 저장하는 것을 기본 요구사항으로 두지 않습니다.
- 운영 로그가 필요할 경우 raw 값 대신 구간화 또는 파생값만 저장할 수 있습니다.
- 일반 사용자 로그인은 MVP 필수 범위에서 제외하고, 관리자 로그인만 필수로 둡니다.

## 기능 요구사항

### FR-01. 기업 정보 입력

사용자는 추천에 필요한 기업 정보를 선택 또는 입력할 수 있어야 한다.

포함 항목:

- 업종
- 업력
- 지역
- 매출
- 직종에서 사용하는 기술
- 폐업 여부
- 신용점수
- 기대출
- 사업장 점유 형태(임대/자가)
- 임대료

세부 조건:

- 가능한 한 선택형 또는 검색형 UI로 제공해야 한다.
- 금액 값은 구간 선택 방식으로 제공할 수 있어야 한다.
- 입력값은 추천 규칙 엔진이 처리 가능한 구조화 데이터로 저장 또는 전달되어야 한다.

### FR-02. 정책자금 추천 결과 반환

시스템은 사용자 입력 조건과 운영 중인 자금 규칙을 기반으로 추천 가능한 정책자금 카드 목록을 반환해야 한다.

세부 조건:

- 추천 결과는 `recommended` 또는 `review_needed` 상태의 자금 카드만 사용자 화면에 노출한다.
- 공통 신청 제한, 제외업종, 체납처럼 추천이 어려운 경우에는 부적격 자금 목록을 노출하지 않고 빈 추천 목록과 일반 안내 문구를 반환할 수 있어야 한다.
- 결과는 내부 `display_priority` 기준으로 정렬하되, 이 값은 사용자 응답에 포함하지 않는다.
- 결과에는 자금명, 간략한 추천 이유, 추천 근거, 신청 전 확인 안내, 자금 소개 요약, 맞춤 제출서류 안내가 포함되어야 한다.
- `review_needed`는 바로 추천 또는 불가로 단정하기 어려워 추가 증빙이나 상담 확인이 필요한 경우에만 사용한다.

### FR-03. 사용자 맞춤 필요 서류 반환

시스템은 사용자 조건과 자금 조건에 따라 필요한 제출 서류 목록을 함께 반환해야 한다.

예시:

- 임대 사업장인 경우 `사업장 임대차계약서`
- 자가 사업장인 경우 `등기부등본`

세부 조건:

- 서류 목록은 자금 규칙과 사용자 상태를 함께 반영해야 한다.
- 서류는 공통 서류와 조건부 서류를 구분할 수 있어야 한다.
- 추천 결과 또는 상세 화면에서 함께 조회 가능해야 한다.
- 필요 서류가 어떤 조건 때문에 붙었는지 설명할 수 있어야 한다.

### FR-04. 자금 상세 정보 조회

사용자는 개별 정책자금의 상세 조건, 지원 내용, 신청 기관, 신청방법 안내 링크 또는 신청 경로를 조회할 수 있어야 한다.

세부 조건:

- 사용자는 추천 결과 목록에서 특정 자금을 선택해 상세 화면으로 이동할 수 있어야 한다.
- 상세 화면에는 자격 조건, 지원 한도, 금리, 신청 기간, 기관 정보가 포함되어야 한다.
- 외부 링크는 직접 신청 버튼이 아니라 해당 자금의 소개 페이지, 공고문, 신청방법 안내 페이지로 연결한다.
- 온라인, 오프라인, 혼합형 신청 경로를 구분할 수 있어야 한다.

### FR-05. 서류 발급 방법 조회

사용자는 각 필요 서류의 발급 방법, 발급 경로, 준비 시 유의사항을 조회할 수 있어야 한다.

세부 조건:

- 서류별 발급 방법은 단계형 안내로 제공될 수 있어야 한다.
- 온라인/오프라인 발급 경로를 구분할 수 있어야 한다.
- 발급 시간, 비용, 유효기간, 재발급 가능 여부 같은 실무 정보가 포함될 수 있어야 한다.

### FR-06. 필요 서류 콘텐츠 관리

관리자는 CMS 또는 DB 기반 관리 화면에서 필요 서류 콘텐츠를 생성, 수정, 삭제할 수 있어야 한다.

세부 조건:

- 관리자 기능은 로그인한 관리자만 접근할 수 있어야 한다.
- 서류명, 발급 방법, 발급 경로, 유의사항 등을 수정할 수 있어야 한다.
- 변경된 콘텐츠는 승인된 운영 데이터 기준으로 사용자 조회 화면에 반영될 수 있어야 한다.

### FR-07. 정책자금 규칙 업데이트 및 승인 관리

관리자는 정책자금 추천 규칙과 자격 조건을 생성, 수정, 갱신할 수 있어야 하며, 문서 업로드 기반 변경 제안도 승인할 수 있어야 한다.

세부 조건:

- 관리자는 공고문, 기관 안내문 등 공식 문서를 업로드할 수 있어야 한다.
- 시스템은 업로드된 문서를 파싱하고, 기존 운영 규칙과 비교해 변경 여부를 탐지할 수 있어야 한다.
- 변경이 감지되면 자금 규칙, 필요 서류 규칙, 자금 소개/신청방법 안내 링크 또는 서류 가이드에 대한 초안 변경안을 생성할 수 있어야 한다.
- 시스템은 변경 초안이 생성되면 관리자에게 검토 알림을 보낼 수 있어야 한다.
- 관리자는 초안을 검토하고 승인, 반려, 수정 후 승인할 수 있어야 한다.
- 승인된 변경만 운영 규칙에 반영되어 사용자 추천 결과에 사용되어야 한다.
- 관리자는 필요 시 관리 화면에서 직접 규칙을 생성하거나 수정할 수 있어야 한다.

### FR-08. 챗봇 기반 질의응답

사용자는 챗봇을 통해 본인에게 해당하는 자금이나 관련 제도에 대해 질문하고 답변을 받을 수 있어야 한다.

범위 메모:

- 본 기능은 `MVP 이후` 범위로 분리한다.
- 추천 자금 설명, 제도 비교, 추가 질문 응답을 지원하는 방향으로 확장할 수 있다.

## 추천 결과 설명 정책

추천 결과에는 사용자에게 도움이 되는 범위에서 아래 정보를 함께 제공하는 방향을 권장합니다.

- 추천된 이유
- 입력값 중 어떤 조건이 충족되었는지
- 신청 전 확인해야 할 안내 문구
- 어떤 서류가 왜 필요한지
- 자금 소개 요약과 상세보기 링크

MVP 사용자 응답에는 `탈락 사유`, `부적격 자금 목록`, `내부 판정 점수`, `대체 가능한 다른 자금 후보`를 포함하지 않습니다. 이런 정보가 필요하면 운영자 검토 화면이나 후속 확장 기능에서 별도 정책과 관리자 승인 기준을 둔 뒤 다룹니다.

## 확정된 운영 원칙

- 추천 서비스의 기준 데이터는 관리자 승인 후 반영된 운영 데이터만 사용합니다.
- 운영 데이터는 최소 `정책자금 규칙`, `필요 서류 규칙`, `서류 발급 가이드`, `자금 안내 링크` 도메인으로 분리합니다.
- 자금 안내 링크는 자금별 소개 페이지, 공고문, 신청방법 안내 페이지를 우선 지원합니다.
- MVP의 변경 이력은 최소 `updated_at`, `updated_by`, `approved_at`, `approved_by` 수준으로 관리합니다.

## 후속 확장 메모

아래 내용은 현재 요구사항에 포함하지 않지만, 추후 규칙 설계와 추천 UX에서 중요하게 다룰 수 있습니다.

- 현재는 조건이 부족하지만 `쉽게 변경 가능한 조건`이 있는 경우 대안 시나리오를 함께 안내하는 기능
- 예: 특정 자금의 신용점수 기준이 `820점`인데 사용자가 `810점` 상태라면, 조건 보완 후 재검토 가능성을 일반 가이드 형태로 안내하는 확장형 추천
- 부적격 자금 목록, 대체 자금 후보, 자동화된 금융 전략 제안, 특정 금융상품 권유는 규제, 리스크, 설명 책임이 크므로 MVP 범위에서 제외합니다.
- 일반 사용자 로그인과 추천 이력 저장은 추후 확장 범위로 검토할 수 있습니다.
