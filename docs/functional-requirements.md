# Functional Requirements

정책자금 추천 웹사이트의 기능 요구사항 문서입니다. 본 문서는 현재 스토리보드와 사용자 메모를 기준으로 MVP 범위와 이후 확장 범위를 정리합니다.

## Document Scope

- 기준일: `2026-04-30`
- 대상 서비스: 정책자금 추천 웹사이트
- 기준 산출물: 스토리보드 `S1` ~ `S5`

## Product Goal

사용자가 자신의 사업 조건을 선택 또는 검색 기반으로 입력하면, 시스템이 신청 가능성이 있는 정책자금과 필요 서류를 함께 추천하고, 상세 자금 정보와 서류 발급 방법까지 이어서 제공하는 것을 목표로 합니다.

## User Roles

### 1. End User

- 정책자금 추천을 받는 일반 사용자
- 사업 상태를 입력하고 추천 자금, 필요 서류, 발급 방법을 확인하는 사용자

### 2. Admin

- 로그인한 관리자만 접근 가능한 운영 사용자
- 필요 서류 콘텐츠와 정책자금 규칙을 관리하는 사용자

## Input Policy

- 사용자 입력 방식은 `선택`과 `검색` 중심으로 통일합니다.
- 금액 관련 항목은 자유 텍스트 입력보다 `선택형 구간값` 중심으로 제공합니다.
- 추천에 필요한 기업 정보는 단계형 입력 경험으로 구성합니다.

## Functional Requirements

### FR-01. 기업 정보 입력

사용자는 추천에 필요한 기업 정보를 선택 또는 입력할 수 있어야 한다.

포함 항목:

- 업종
- 업력
- 지역
- 매출
- 직종에서 사용하는 기술
- 폐업 여부
- 신용점수
- 기대출
- 사업장 점유 형태(임대/자가)
- 임대료

세부 조건:

- 가능한 한 선택형 또는 검색형 UI로 제공해야 한다.
- 금액 값은 구간 선택 방식으로 제공할 수 있어야 한다.
- 입력값은 추천 규칙 엔진이 처리 가능한 구조화 데이터로 저장 또는 전달되어야 한다.

### FR-02. 정책자금 추천 결과 반환

시스템은 사용자 입력 조건과 자금 규칙을 기반으로 신청 가능성이 있는 정책자금 목록을 반환해야 한다.

세부 조건:

- 추천 결과는 다건 목록 형태로 제공되어야 한다.
- 결과에는 자금명, 핵심 조건, 요약 정보가 포함되어야 한다.
- 추천 결과에는 사용자에게 왜 해당 자금이 추천되었는지에 대한 근거를 표시할 수 있어야 한다.

### FR-03. 사용자 맞춤 필요 서류 반환

시스템은 사용자 조건에 따라 필요한 제출 서류 목록을 함께 반환해야 한다.

예시:

- 임대 사업장인 경우 `사업장 임대차계약서`
- 자가 사업장인 경우 `등기부등본`

세부 조건:

- 서류 목록은 자금 규칙과 사용자 상태를 함께 반영해야 한다.
- 서류는 공통 서류와 조건부 서류를 구분할 수 있어야 한다.
- 추천 결과 또는 상세 화면에서 함께 조회 가능해야 한다.

### FR-04. 자금 상세 정보 조회

사용자는 개별 정책자금의 상세 조건, 지원 내용, 신청 기관, 신청 링크 또는 신청 경로를 조회할 수 있어야 한다.

세부 조건:

- 사용자는 추천 결과 목록에서 특정 자금을 선택해 상세 화면으로 이동할 수 있어야 한다.
- 상세 화면에는 자격 조건, 지원 한도, 금리, 신청 기간, 기관 정보가 포함되어야 한다.
- 신청 링크 또는 외부 신청 경로가 제공될 수 있어야 한다.

### FR-05. 서류 발급 방법 조회

사용자는 각 필요 서류의 발급 방법, 발급 경로, 준비 시 유의사항을 조회할 수 있어야 한다.

세부 조건:

- 서류별 발급 방법은 단계형 안내로 제공될 수 있어야 한다.
- 온라인/오프라인 발급 경로를 구분할 수 있어야 한다.
- 발급 시간, 비용, 유효기간, 재발급 가능 여부 같은 실무 정보가 포함될 수 있어야 한다.

### FR-06. 필요 서류 콘텐츠 관리

관리자는 CMS 또는 DB 기반 관리 화면에서 필요 서류 콘텐츠를 생성, 수정, 삭제할 수 있어야 한다.

세부 조건:

- 관리자 기능은 로그인한 관리자만 접근할 수 있어야 한다.
- 서류명, 발급 방법, 발급 경로, 유의사항 등을 수정할 수 있어야 한다.
- 변경된 콘텐츠는 사용자 조회 화면에 반영될 수 있어야 한다.

### FR-07. 정책자금 규칙 관리

관리자는 정책자금 추천 규칙과 자격 조건을 생성, 수정, 갱신할 수 있어야 한다.

세부 조건:

- 추천 규칙은 사용자 입력 조건과 매칭 가능한 구조여야 한다.
- 자금별 자격 조건, 필요 서류 조건, 기관 정보, 신청 링크를 관리할 수 있어야 한다.
- 규칙 변경 후 사용자 추천 결과에 반영될 수 있어야 한다.

### FR-08. 챗봇 기반 질의응답

사용자는 챗봇을 통해 본인에게 해당하는 자금이나 관련 제도에 대해 질문하고 답변을 받을 수 있어야 한다.

범위 메모:

- 본 기능은 `MVP 이후` 범위로 분리할 수 있다.
- 추천 자금 설명, 제도 비교, 추가 질문 응답을 지원하는 방향으로 확장할 수 있다.

## Recommendation Explanation Policy

추천 결과에는 가능한 경우 아래 정보를 함께 제공하는 방향을 권장합니다.

- 추천된 이유
- 입력값 중 어떤 조건이 충족되었는지
- 어떤 조건이 아직 부족한지

이는 추천의 신뢰도를 높이고, 사용자가 다음 행동을 이해하는 데 도움을 줍니다.

## Future Enhancement Notes

아래 내용은 현재 요구사항 초안에 포함하지 않지만, 추후 규칙 설계와 추천 UX에서 중요하게 다룰 수 있습니다.

- 현재는 조건이 부족하지만 `쉽게 변경 가능한 조건`이 있는 경우 대안 시나리오를 함께 안내하는 기능
- 예: 특정 자금의 신용점수 기준이 `820점`인데 사용자가 `830점` 상태라면, 심사 기간 중 고려 가능한 금융 행동과 이후 대환 방식 등을 안내하는 확장형 추천

이 영역은 규제, 금융 리스크, 설명 책임이 크므로 MVP 이후 별도 정책과 검토 기준을 두고 설계하는 것이 적절합니다.
