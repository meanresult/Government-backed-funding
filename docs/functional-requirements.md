# Functional Requirements

정책자금 추천 웹사이트의 기능 요구사항 문서입니다. 본 문서는 현재 스토리보드, 운영 방향, MVP 의사결정을 기준으로 사용자 기능과 운영 기능을 정리합니다.

## Document Scope

- 기준일: `2026-05-01`
- 대상 서비스: 정책자금 추천 웹사이트
- 기준 산출물: 스토리보드 `S1` ~ `S5`

## Product Goal

사용자가 자신의 사업 조건을 선택 또는 검색 기반으로 입력하면, 시스템이 신청 가능성이 있는 정책자금과 필요 서류를 함께 추천하고, 상세 자금 정보와 서류 발급 방법까지 이어서 제공하는 것을 목표로 합니다.

동시에 운영자는 공고 문서를 업로드하면 시스템이 변경 여부를 검토하고, 초안 규칙을 생성한 뒤 관리자 승인 후에만 운영 규칙에 반영되도록 관리할 수 있어야 합니다.

## User Roles

### 1. End User

- 정책자금 추천을 받는 일반 사용자
- 사업 상태를 입력하고 추천 자금, 필요 서류, 발급 방법을 확인하는 사용자

### 2. Admin

- 로그인한 관리자만 접근 가능한 운영 사용자
- 필요 서류 콘텐츠와 정책자금 규칙을 관리하고 승인하는 사용자

## Input Policy

- 사용자 입력 방식은 `선택`과 `검색` 중심으로 통일합니다.
- 금액 관련 항목은 자유 텍스트 입력보다 `선택형 구간값` 중심으로 제공합니다.
- 추천에 필요한 기업 정보는 단계형 입력 경험으로 구성합니다.
- 입력값은 추천 규칙 엔진이 평가할 수 있는 구조화 데이터 형태로 전달되어야 합니다.

## Sensitive Input Handling Policy

- `신용점수`, `기대출`은 추천 요청 시점의 평가 입력값으로 사용합니다.
- MVP에서는 raw 값을 영구 저장하는 것을 기본 요구사항으로 두지 않습니다.
- 운영 로그가 필요할 경우 raw 값 대신 구간화 또는 파생값만 저장할 수 있습니다.
- 일반 사용자 로그인은 MVP 필수 범위에서 제외하고, 관리자 로그인만 필수로 둡니다.

## Functional Requirements

### FR-01. 기업 정보 입력

사용자는 추천에 필요한 기업 정보를 선택 또는 입력할 수 있어야 한다.

포함 항목:

- 업종
- 업력
- 지역
- 매출
- 직종에서 사용하는 기술
- 폐업 여부
- 신용점수
- 기대출
- 사업장 점유 형태(임대/자가)
- 임대료

세부 조건:

- 가능한 한 선택형 또는 검색형 UI로 제공해야 한다.
- 금액 값은 구간 선택 방식으로 제공할 수 있어야 한다.
- 입력값은 추천 규칙 엔진이 처리 가능한 구조화 데이터로 저장 또는 전달되어야 한다.

### FR-02. 정책자금 추천 결과 반환

시스템은 사용자 입력 조건과 운영 중인 자금 규칙을 기반으로 정책자금별 판정 결과와 추천 목록을 반환해야 한다.

세부 조건:

- 자금별로 `적합`, `근사 부적합`, `부적합` 상태를 구분할 수 있어야 한다.
- `적합` 판정 자금은 추천 목록에 모두 포함되어야 한다.
- `근사 부적합` 자금은 별도 보완 안내와 함께 노출할 수 있어야 한다.
- 결과는 우선순위 또는 점수 기준으로 정렬될 수 있어야 한다.
- 결과에는 자금명, 핵심 조건, 요약 정보, 추천 근거가 포함되어야 한다.
- 반환 데이터에는 충족 조건, 부족 조건, 일반적인 다음 액션 또는 대체 가능한 다른 자금 후보를 포함할 수 있어야 한다.

### FR-03. 사용자 맞춤 필요 서류 반환

시스템은 사용자 조건과 자금 조건에 따라 필요한 제출 서류 목록을 함께 반환해야 한다.

예시:

- 임대 사업장인 경우 `사업장 임대차계약서`
- 자가 사업장인 경우 `등기부등본`

세부 조건:

- 서류 목록은 자금 규칙과 사용자 상태를 함께 반영해야 한다.
- 서류는 공통 서류와 조건부 서류를 구분할 수 있어야 한다.
- 추천 결과 또는 상세 화면에서 함께 조회 가능해야 한다.
- 필요 서류가 어떤 조건 때문에 붙었는지 설명할 수 있어야 한다.

### FR-04. 자금 상세 정보 조회

사용자는 개별 정책자금의 상세 조건, 지원 내용, 신청 기관, 신청 링크 또는 신청 경로를 조회할 수 있어야 한다.

세부 조건:

- 사용자는 추천 결과 목록에서 특정 자금을 선택해 상세 화면으로 이동할 수 있어야 한다.
- 상세 화면에는 자격 조건, 지원 한도, 금리, 신청 기간, 기관 정보가 포함되어야 한다.
- 신청 링크는 가능한 경우 기관 대표 페이지가 아니라 해당 자금으로 연결되는 외부 딥링크를 지원해야 한다.
- 온라인, 오프라인, 혼합형 신청 경로를 구분할 수 있어야 한다.

### FR-05. 서류 발급 방법 조회

사용자는 각 필요 서류의 발급 방법, 발급 경로, 준비 시 유의사항을 조회할 수 있어야 한다.

세부 조건:

- 서류별 발급 방법은 단계형 안내로 제공될 수 있어야 한다.
- 온라인/오프라인 발급 경로를 구분할 수 있어야 한다.
- 발급 시간, 비용, 유효기간, 재발급 가능 여부 같은 실무 정보가 포함될 수 있어야 한다.

### FR-06. 필요 서류 콘텐츠 관리

관리자는 CMS 또는 DB 기반 관리 화면에서 필요 서류 콘텐츠를 생성, 수정, 삭제할 수 있어야 한다.

세부 조건:

- 관리자 기능은 로그인한 관리자만 접근할 수 있어야 한다.
- 서류명, 발급 방법, 발급 경로, 유의사항 등을 수정할 수 있어야 한다.
- 변경된 콘텐츠는 승인된 운영 데이터 기준으로 사용자 조회 화면에 반영될 수 있어야 한다.

### FR-07. 정책자금 규칙 업데이트 및 승인 관리

관리자는 정책자금 추천 규칙과 자격 조건을 생성, 수정, 갱신할 수 있어야 하며, 문서 업로드 기반 변경 제안도 승인할 수 있어야 한다.

세부 조건:

- 관리자는 공고문, 기관 안내문 등 공식 문서를 업로드할 수 있어야 한다.
- 시스템은 업로드된 문서를 파싱하고, 기존 운영 규칙과 비교해 변경 여부를 탐지할 수 있어야 한다.
- 변경이 감지되면 자금 규칙, 필요 서류 규칙, 신청 링크 또는 서류 가이드에 대한 초안 변경안을 생성할 수 있어야 한다.
- 시스템은 변경 초안이 생성되면 관리자에게 검토 알림을 보낼 수 있어야 한다.
- 관리자는 초안을 검토하고 승인, 반려, 수정 후 승인할 수 있어야 한다.
- 승인된 변경만 운영 규칙에 반영되어 사용자 추천 결과에 사용되어야 한다.
- 관리자는 필요 시 관리 화면에서 직접 규칙을 생성하거나 수정할 수 있어야 한다.

### FR-08. 챗봇 기반 질의응답

사용자는 챗봇을 통해 본인에게 해당하는 자금이나 관련 제도에 대해 질문하고 답변을 받을 수 있어야 한다.

범위 메모:

- 본 기능은 `MVP 이후` 범위로 분리한다.
- 추천 자금 설명, 제도 비교, 추가 질문 응답을 지원하는 방향으로 확장할 수 있다.

## Recommendation Explanation Policy

추천 결과에는 가능한 경우 아래 정보를 함께 제공하는 방향을 권장합니다.

- 추천된 이유
- 입력값 중 어떤 조건이 충족되었는지
- 어떤 조건이 아직 부족한지
- 어떤 서류가 왜 필요한지
- 다음 액션 또는 대체 가능한 다른 자금 후보

`근사 부적합` 안내는 MVP에서 보수적이고 일반적인 문구를 우선 적용하고, 구체적인 금융행동 권유 수준의 안내는 별도 정책과 관리자 승인 기준이 있어야 합니다.

## Confirmed Operational Decisions

- 추천 서비스의 기준 데이터는 관리자 승인 후 반영된 운영 데이터만 사용합니다.
- 운영 데이터는 최소 `정책자금 규칙`, `필요 서류 규칙`, `서류 발급 가이드`, `신청 링크` 도메인으로 분리합니다.
- 신청 링크는 자금별 외부 딥링크를 지원합니다.
- MVP의 변경 이력은 최소 `updated_at`, `updated_by`, `approved_at`, `approved_by` 수준으로 관리합니다.

## Future Enhancement Notes

아래 내용은 현재 요구사항에 포함하지 않지만, 추후 규칙 설계와 추천 UX에서 중요하게 다룰 수 있습니다.

- 현재는 조건이 부족하지만 `쉽게 변경 가능한 조건`이 있는 경우 대안 시나리오를 함께 안내하는 기능
- 예: 특정 자금의 신용점수 기준이 `820점`인데 사용자가 `810점` 상태라면, 조건 보완 후 재검토 가능성을 일반 가이드 형태로 안내하는 확장형 추천
- 자동화된 금융 전략 제안이나 특정 금융상품 권유는 규제, 리스크, 설명 책임이 크므로 MVP 범위에서 제외합니다.
- 일반 사용자 로그인과 추천 이력 저장은 추후 확장 범위로 검토할 수 있습니다.
