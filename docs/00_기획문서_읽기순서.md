# 00. 기획문서 읽기 순서

정책자금 추천 서비스 문서를 처음 읽는 사람이 `무엇을 만들고`, `어떤 기능이 필요하며`, `어떤 흐름으로 동작하고`, `어떤 규칙과 서류 기준으로 구현되는지`를 빠르게 판단할 수 있도록 정리한 안내 문서입니다.

## 현재 구현 읽기 흐름 — 2026-09-18

현재 방식은 **문서 기반 개발 + 코드 기반 운영**이다. AI는 Playwright MCP로 사이트를 확인해 코드를 작성·수정하고, 정기 수집은 검증된 Python Playwright 코드를 실행한다. 문서 작성 완료와 수집기 구현·배포 완료는 구분한다.

1. [AGENTS.md](../AGENTS.md) → [GPT.md](../GPT.md): AI가 따를 공통 작업·환경·보안·검증 규칙
2. [16_RAW_수집_가공_분리_설계.md](16_RAW_수집_가공_분리_설계.md): 개발/운영 역할 분리, S3 RAW 경계, ID·해시·첨부 변경·실패·재처리
3. [01_collector_mvp.md](tasks/01_collector_mvp.md): 첫 수집기의 입력·구현 순서·산출물·합격 기준과 AI 요청문
4. [collector.md](runbooks/collector.md): 실행 준비·성공 판정·장애 분석·수정·재실행. 실제 명령은 코드 검증 후 기록
5. [15_대화형_정책자금_안내_전환계획.md](15_대화형_정책자금_안내_전환계획.md): 후속 정형화·Snowflake·시멘틱 레이어·기업 상태 후속 질문과 답변
6. [02_기능요구사항.md](02_기능요구사항.md): 상단 `RI-01~10`, `CF-01~07` 요구사항과 단계별 범위
7. [03_시스템_아키텍처.md](03_시스템_아키텍처.md), [04_기술_아키텍처.md](04_기술_아키텍처.md): 상단의 수집·가공·대화 경계와 현재 기술 구성

## 문서 위치와 역할

아래는 작성된 문서의 구조다. 실제 코드·YAML 설정·RAW JSON Schema의 구현 예정 위치는 작업 지시서에서 별도로 관리한다.

```text
government-backed-funding/
├── AGENTS.md                           # AI 지침 진입점
├── GPT.md                              # 공통 개발·보안·검증 규칙
├── README.md                           # 프로젝트 소개·환경 준비
└── docs/
    ├── 00_기획문서_읽기순서.md           # 이 문서: 전체 지도
    ├── 02_기능요구사항.md               # 현재 요구사항은 상단 절
    ├── 03_시스템_아키텍처.md            # 현재 시스템 흐름은 상단 절
    ├── 04_기술_아키텍처.md              # 현재 기술 구성은 상단 절
    ├── 12_문서파싱_변경감지_전략.md      # 후속 파싱·업무 조건 비교
    ├── 15_대화형_정책자금_안내_전환계획.md # 후속 저장·대화 범위
    ├── 16_RAW_수집_가공_분리_설계.md     # 수집·증분·완료 계약
    ├── tasks/
    │   └── 01_collector_mvp.md          # AI에게 전달할 구현 지시서
    └── runbooks/
        └── collector.md                # 실행·결과 확인·장애 복구
```

### 상황별 최소 읽기

- 코드 구현 요청: `AGENTS.md` → `GPT.md` → `16` → `tasks/01_collector_mvp.md`
- 실행·장애 대응: `GPT.md` → `runbooks/collector.md` → 필요한 `16` 계약·작업 지시서
- 후속 정형화·대화 설계: `16`의 RAW 완료 경계 → `15` → `02·03·04`의 최신 절

지침은 AI가 읽고, 실제 URL·범위·한도는 구현될 `configs/sources/` 설정을 코드가 읽는다. 설정 값을 여러 문서에 복제하지 않는다. 기존 문서를 삭제하거나 이동하지 않고 현재 기준과 후속 참고를 구분한다.

기존 문서에서 `추천 API 우선`, `챗봇 MVP 제외`, `PostgreSQL 필수`, `크롤링 후순위`로 적힌 내용은 이전 웹서비스 설계다. `수집 전에 정책자금 스키마 확정`, `수집 성공에 Snowflake 적재 필요`, `정기 실행마다 Agent가 MCP로 탐색`, `사이트별 어댑터를 만들지 않음`도 현재 기준이 아니다. 수집·가공 경계는 `16`, 후속 대화 범위는 `15`와 `02·03·04`의 최신 절을 따른다. 기존 문서별 기준표와 읽기 트랙은 아래에 후속 참고용으로 보존한다.

도메인 참고는 `06·07·13`, 검토·근거·감사 원칙은 `11·12·14`를 사용한다. `01·08·09·10`의 화면·추천 API·PostgreSQL DDL은 초기 선행 구현 대상이 아니다. 과거 예시의 자격 수치와 기간은 현재 정책으로 간주하지 않고 수집한 최신 공식 근거로 재확인한다. 기존 엑셀 WBS는 이 전환 일정이 반영되기 전까지 현재 구현 순서의 기준으로 사용하지 않는다.
