# 01. 단일 기관 RAW 수집기 구현 지시서

- 작성일: `2026-09-18`
- 상태: SEMAS 수집기 구현 완료 / 제한된 로컬 실사이트 검증 완료 / S3 실증 전
- 목표: 지정된 기관의 게시판 URL 하나를 시작점으로, 검증된 코드가 공고·첨부 원본을 로컬 또는 S3 RAW에 반복 수집하게 한다.
- 이번 문서의 완료는 수집 코드·실제 사이트·S3 실증 완료를 의미하지 않는다.

## 1. 작업 전 읽을 문서

1. [GPT.md](../../GPT.md): 공통 작업·환경·보안 규칙
2. [16_RAW_수집_가공_분리_설계.md](../16_RAW_수집_가공_분리_설계.md): ID·해시·불변 버전·완료 manifest 계약
3. [collector.md](../runbooks/collector.md): 실행·결과 확인·복구 절차

이 문서는 `16`의 데이터 계약을 구현 가능한 작업으로 나눈다. 세부 필드의 기준을 중복 정의하지 않으며, 계약 변경이 필요하면 `16`과 테스트를 함께 수정한다.

## 2. 구현 전 확정할 입력

| 입력 | 현재 상태 | 없을 때 허용되는 작업 |
| --- | --- | --- |
| 기관명·고정 `source_id`·첫 게시판 URL | 미정 | 공통 코드와 고정 테스트 자료 작성 |
| 허용 도메인·첨부 호스트·수집 대상 게시판 | 미정 | 설정 검증 및 접근 제한 테스트 |
| 첫 수집 기간·페이지/공고 수·과거 공고 재확인 범위 | 미정 | 범위·한도 종료 테스트 |
| 요청 간격·시간 제한·최대 재시도 | 미정 | 설정 필수값·상한 검증 |
| S3 버킷·리전·prefix·승인된 자격증명 제공 방식 | 미정 | 로컬 저장 및 S3 대역을 이용한 테스트 |
| 실제 사이트·S3 테스트 실행 범위 | 미정 | 외부 접근 없는 테스트 |

사용자가 입력을 정하면 비밀값을 제외한 운영 값은 `configs/sources/<source_id>.yaml`에 기록한다. 동일 URL·제한값을 이 문서에 다시 복사하지 않는다. 비밀키·토큰은 설정 파일에도 넣지 않는다. 미정 입력이 있다고 공통 테스트 작업까지 중단할 필요는 없지만, 실제 기관용 어댑터와 S3 실증 완료를 주장하지 않는다.

## 3. 포함 범위와 제외 범위

### 포함

- AI + Playwright MCP로 승인된 사이트의 목록·상세·첨부·페이지 이동을 확인
- Python Playwright 기반의 반복 실행 수집기와 기관별 어댑터 작성
- HTML 응답(확보 가능한 경우), 렌더링 DOM, 본문 텍스트, PDF/HWP/HWPX 원본 저장
- RAW 메타데이터 검증, 공고 ID, 파일 SHA-256, 변경 비교 해시, 불변 버전 관리
- 로컬 저장 검증 경로와 실제 S3 저장 경로를 구분하여 구현
- 신규·변경·변경 없음·부분 실패·완전 실패 기록과 안전한 재실행
- 단위·통합·제한된 실사이트 테스트와 운영 문서 갱신

### 제외

- 정기 수집마다 LLM이 탐색하거나 코드를 생성하는 방식
- 자동 장애 수정·운영 코드 교체·배포
- PDF/HWP 내용 파싱, OCR, 정책 조건 추출과 비즈니스 스키마 확정
- Snowflake·시멘틱 레이어·추천 API·웹 UI
- Airflow 연결, EC2 자원 생성과 운영 배포
- 로그인·신청 제출·접근 제한 우회, 승인되지 않은 사이트 추가

## 4. 산출물과 책임

아래는 구현 시 만들어야 할 경로다. 현재 존재하거나 실행 가능한 파일이라는 뜻은 아니다.

| 경로 | 책임 |
| --- | --- |
| `workers/collector/__main__.py`, `runner.py` | 공통 실행 진입점, 설정 검증, 실행 ID·범위·상태 관리 |
| `workers/collector/adapters/` | 기관별 목록·상세·첨부·페이지 이동. 공통 저장 코드 복제 금지 |
| `workers/collector/`의 공통 모듈 | 브라우저·다운로드·해시·로컬/S3 저장·상태 복구 |
| `configs/sources/<source_id>.yaml` | 기관별 비밀정보 없는 실행 설정 |
| `schemas/raw/metadata_v1.json` | `16`의 RAW 운영 메타데이터 계약을 검증할 JSON Schema |
| `tests/collector/`, `tests/fixtures/collector/` | 고정 HTML·첨부 자료, 단위·통합·회귀 테스트 |
| `pyproject.toml`, `uv.lock` | 실제 사용하는 Python 의존성과 잠금 버전 |
| [collector.md](../runbooks/collector.md) | 검증된 명령·결과 위치·장애 복구·검증 기록 |

설정은 YAML 데이터로만 읽는다. 어댑터는 코드에 등록된 허용 목록으로 선택하고, 설정 문자열을 임의 Python 코드·셸 명령·동적 모듈 경로로 실행하지 않는다. `source_id`와 파일명은 경로 탈출·충돌을 방지하도록 검증한다.

개발 도구의 Playwright MCP 설치를 Python 수집기의 설치로 간주하지 않는다. 브라우저와 OS 의존성 설치 방법도 기록한다. 문서 요청만으로 의존성을 설치하거나 위 코드 파일을 빈 구현으로 채우지 않는다.

## 5. 구현 순서

1. **입력과 계약 확인**: 현재 변경 내역을 확인하고 미정 입력·권한 범위를 보고한다. RAW 스키마와 설정 검증부터 구현한다.
2. **고정 자료로 공통 흐름 구현**: 테스트용 사이트와 첨부를 이용해 목록·상세·다운로드·로컬 저장·상태 처리를 검증한다.
3. **실제 사이트 탐색**: 입력 확정 후 MCP로 사이트 구조와 제한을 확인한다. 관찰하지 않은 버튼·선택자·다운로드 URL을 추측하지 않는다.
4. **기관별 어댑터 작성**: 관찰 결과를 코드와 테스트로 고정한다. 매 실행 시 목록을 발견하며 특정 공고 몇 개의 URL만 하드코딩하지 않는다.
5. **재실행·변경·실패 검증**: 변경 테스트는 고정 자료에서 수행한다. 실제 기관 사이트의 게시물을 수정하지 않는다.
6. **S3 실증**: 승인된 범위에서 수집하고 S3에서 다시 읽어 원본·manifest·해시를 대조한다.
7. **문서와 결과 보고**: 아래 합격 기준의 실제 증거를 남기고, 검증하지 못한 항목은 미완료로 유지한다.

목록/본문 요소를 찾을 때 안정적인 역할·이름·속성을 우선하고, 페이지 순회가 실제로 진행되는지 확인한다. 오류 없는 종료만으로 전체 범위 수집 성공을 판정하지 않는다.

## 6. 실행 인터페이스와 관측 계약

공통 진입점은 `python -m workers.collector`로 구현하고, 최소 `--source SOURCE_ID`, `--storage local|s3`와 도움말을 제공한다. 이 인터페이스는 구현 목표이며 현재 실행할 수 없다. 실제 옵션·종료 코드는 구현 및 테스트 후 운영 문서에 확정한다.

- 시작 시 source 설정·RAW 계약·자격증명 가용성을 검증하고, 잘못된 설정으로 외부 쓰기를 시작하지 않는다.
- 로컬과 S3 저장 대상은 명시적으로 선택하며 실패 시 다른 대상으로 몰래 전환하지 않는다.
- 실행마다 `run_id`, 코드 버전, 설정 해시, 시작/종료 UTC, 대상 범위, 방문 URL, 발견·저장·변경 없음·실패 건수와 오류 종류를 기록한다.
- 코드·설정 변경은 공고 내용 변경과 구분한다. `content_hash`에 실행 시각이나 코드 버전을 섞지 않는다.
- 범위가 완전히 검증된 실행만 성공 종료한다. 일부 공고·첨부·페이지의 실패 또는 한도에 따른 미완료는 전체 성공과 다른 비정상 종료로 알린다.
- 실제 신규 공고 0건과 목록 파싱 실패를 구분한다. 마지막 페이지/빈 목록 표시·중복 페이지 반복·개수 급감 등 근거를 확인하고, 판단이 불확실하면 검토 상태로 남긴다.
- 공고별 정상 완료본은 보존하되, 미완료 실행의 전체 범위 확인 시각이나 이어서 수집할 위치를 완료된 것처럼 앞당기지 않는다.
- 같은 기관의 동시 실행을 막는다. 재시도 시 이미 검증된 완료본을 중복 발행하거나 덮어쓰지 않는다.
- 실패 시 현재 URL·스크린샷·HTML·가능한 추적 자료를 제한된 경로에 저장한다. 세션·인증정보를 제거하고 Git에는 넣지 않는다.

## 7. 합격 기준

구현자가 검증 후 각 항목을 체크하고 실행 ID·테스트 이름·증거 위치를 기록한다. 문서 작성 시점에는 모두 미검증이다.

- [ ] `AC-01` 고정 자료에서 목록·다음 페이지·상세·본문·첨부 전체 흐름이 검증된다.
- [ ] `AC-02` 실제 공고의 본문과 첨부를 S3에서 다시 읽어 원본 바이트·크기·해시를 대조한다. 사이트에 없는 첨부 형식은 실사이트 검증으로 표시하지 않는다.
- [ ] `AC-03` 같은 공고 재실행 시 ID 유지, 불필요한 버전·가공 대상 미생성, 재확인 이력 기록을 확인한다.
- [ ] `AC-04` 고정 자료의 본문 수정·첨부만 교체·첨부 추가/삭제가 새 버전을 만들며 기존 원본을 보존한다.
- [ ] `AC-05` 다운로드/업로드 중간 실패 시 PARTIAL로 남고, 불완전 manifest와 상태가 완료본으로 노출되지 않는다.
- [ ] `AC-06` COMPLETE manifest 저장 뒤 상태 갱신 실패를 재실행으로 복구하며 중복 발행하지 않는다.
- [ ] `AC-07` 잘못된 요소 선택, 빈 본문, 다음 페이지 순회 실패, PDF 대신 로그인 HTML 응답을 성공과 구분한다.
- [ ] `AC-08` 실제 신규 0건과 탐색 실패, 확인된 첨부 삭제와 다운로드 실패를 구분한다.
- [ ] `AC-09` 과거 공고 재확인 범위를 실행하며, 확인하지 않은 범위와 한도 도달을 기록한다.
- [ ] `AC-10` 허용 도메인·리다이렉트·내부망 제한과 경로 검증, 민감정보 제외를 테스트한다.
- [ ] `AC-11` 정상 수집이 LLM·MCP·Codex 앱 없이 headless 코드로 실행된다. Python/브라우저 설치 방법과 실행 명령이 기록된다.
- [ ] `AC-12` 실행 결과·종료 코드·실패 증거·재시도 절차가 운영 문서와 일치한다.

실제 사이트와 S3 입력이 없으면 `AC-02`를 비롯한 외부 실증 항목은 미완료다. 로컬·대역 테스트 결과만으로 MVP 완료를 선언하지 않는다. Docker/EC2 검증은 이 MVP 이후 별도 단계로 남긴다.

## 8. AI에게 전달할 작업 명령

다음은 이 작업을 명시적으로 시작할 때 사용할 요청문이다.

> GPT.md, docs/16_RAW_수집_가공_분리_설계.md, docs/tasks/01_collector_mvp.md를 읽고 단일 기관 수집기를 구현해줘. 미정 입력을 먼저 확인하고, 입력이 없으면 공통 코드와 고정 자료 테스트까지만 진행해줘. 실제 사이트가 정해지면 Playwright MCP로 확인하고, 정기 실행은 LLM 없이 동작하는 Python Playwright 코드로 작성해줘. 합격 기준을 테스트하고 실제 검증과 미검증을 구분해 보고해줘. 실행 방법과 증거 위치는 docs/runbooks/collector.md에 갱신해줘. Airflow·Snowflake 연결, EC2 생성, 운영 배포는 하지 마.

문서 변경만으로 구현·수집이 자동 시작되지는 않는다. 사용자의 구현 요청과 허용된 외부 실행 범위를 확인한 뒤 수행한다.
